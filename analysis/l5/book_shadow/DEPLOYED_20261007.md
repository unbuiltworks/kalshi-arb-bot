## THE DEFECT: L5 activity is not being recorded

Every cycle logs **`activity poll failed: HTTPError`**. So:

- **both outcome books ARE accumulating** (the artifact nothing else in
  the repo has);
- **L5's own fills are NOT.**

That is the stream needed to locate the turn against L5's actions. Until
it works, the tape answers "what did both books look like" but **not**
"what did both books look like *when L5 turned*" — which is the question
the collector was built for.

And the log carries only `HTTPError`, **not the status code or body** —
the same observability hole that cost a window on Attempt 5's 400. The
fix is the same shape as `VenueHTTPError`: capture status, body and
allowlisted headers. Not applied tonight, because the owner's instruction
is not to change the collector's research logic and because tennis/soccer
book accumulation should not wait on it.

Likely causes, untested and therefore not asserted: a changed data-api
path or parameter, an egress restriction on the activity host, or a
rejected address parameter.

## Evidence semantics, preserved

REST sampling is **same-second / reachability evidence, never strict
causality**. `data-api` activity timestamps are whole seconds and REST
polling locates a crossing only to within one poll interval, so the tape
supports "was the complement reachable, and on which token's book, in the
seconds around the turn" at **±1 poll interval in receive order, ±1 s in
venue time**. The dual-token CLOB websocket is the separate build that
would give ms venue stamps; collection is not waiting on it.
