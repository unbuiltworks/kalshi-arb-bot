## 4. A defect the verification found

**`TRANSPORT_CANNOT_ARM` was unreachable for a one-window campaign — the only
shape this programme runs.**

The gate refuses when the caller states the transport's own arm check would
fail: the Q1 handshake is absent, so `PMUSTransport.arm()` raises `NotArmed`
one call later. It exists so your window is not consumed by a process that
could never place an order. It is the repair for 0145z — claim written at
01:45:01.572, `t.arm()` raising at 01:45:18, one of three authorized windows
gone with no order and no possibility of one.

It was nested inside `if mw > 1:`. Measured on the real boundary, handshake
absent and `transport_armable` False:

| `max_windows` | before the fix |
|---|---|
| **1** | **CLAIM GRANTED, lock line written — the window is spent** |
| 2 | refused `TRANSPORT_CANNOT_ARM` |
| 4 | refused `TRANSPORT_CANNOT_ARM` |

The repair protected every case except the one in use. Hoisted to
function-body level, before **both** claim paths — the mandate's two-level
claim and the single-window claim at step 11 — because the property is about
the transport, not about how many windows were approved. All of 1, 2, 4 and 8
now refuse and write no lock.

Nothing is widened: `None` still means "not stated" and behaves as before,
only an explicit `False` refuses, and a campaign-only process could never arm
anyway. The only change is that the window survives.

15 tests in `tests/test_l5_one_window_transport_arm_gate.py`, including a
structural assertion that the gate sits at function-body indent and precedes
`if mw > 1:`, so it cannot regress by re-indentation.

### Why this matters for the sequence

On the **currently deployed** SHA this defect is live. It is not reachable
today because `L5_SHADOW_ONLY=1` is the first gate and refuses before any
claim is written — so publishing the approval now would spend nothing. But if
the shadow lock were cleared on the deployed SHA without the Q1 handshake in
place, the window would be spent for nothing.

**So the candidate should be deployed before the approval is acted on**, and
that is now a safety reason rather than a preference.
