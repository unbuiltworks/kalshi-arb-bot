### TTE convention — verified, not assumed

The trailing integer in `eventSlug` is the window **OPEN** epoch.
**20,000/20,000** compared fills matched the market's `eventStartTime`;
**0/20,000** matched `endDate`. Example: slug `btc-updown-5m-1773914700`,
market start `2026-03-19T10:05:00Z`, end `10:10:00Z`, question
"6:05AM-6:10AM ET". So **`TTE = open_epoch + duration − t`**. The run
refuses to evaluate a TTE rule if this verification fails.

## Q7 — CAPACITY from the measured mechanism

L5 is **buy-only**, so within one event cash outlay is **monotone**:
redemption arrives only at settlement, after the window closes. Therefore
**peak USDC outlay = total outlay for that event**, and that is the binding
deployed-capital figure.

### Working backward from $480/day

  size, i.e. return on deployed dollar from 1.180% to **1.84%–4.09%**.

### Verdict: $480/day is economics L5 itself never demonstrated pre-incentive

Stated plainly, because the arithmetic says so:

1. L5's own pre-incentive trading-only peak was **~$240/day**; $480/day is
   **2.00x** of its own best demonstrated pre-incentive day.
2. Pre-incentive **rebates add $95.72/day** (MAKER_REBATE $7,367.65 +
   TAKER_REBATE $3,161.66 over 110 days, kept strictly separate from trading
   P&L). Even the most generous stack — confirmed trading $307.90/day **plus**
   all pre-incentive rebates — reaches **$403.62/day**, still **16% short**.
3. **Every REWARD dollar in the corpus ($28,797.69, 20 rows) is
   post-2026-08-01.** Post-incentive incentive income totals **$61,022.43**
   against **$10,529.31** pre-incentive.

So **$480/day is not reachable from the measured pre-incentive mechanism by
any single lever this corpus can validate.** It is reachable only by
(a) 2.0x–3.5x more deployed capital whose depth support is **UNAVAILABLE**,
(b) 1.6x–3.5x more eligible events than L5 itself ever took, or (c)
incentive-era reward economics that are **post-incentive and must stay
locked** absent source-confirmed equivalence for our account. This
corroborates `CANONICAL_L5_MODEL.md`: the $480/day target is an
**incentive-era artifact**, not a pre-incentive capacity figure.

fill allowed to stand. Cumulative replay would confound the rules and
understate every one but the first to bind.

   **no replay inside the current envelope can test the strategy at all.**
2. **The 5c EXTEND gate is the largest purely *behavioural* suppressor.** It

## The smallest set of empirically supported rule changes

Each is entailed by a measurement above. **No threshold is optimized** — each
change is either "the measured value differs from the coded one" or "the
coded value is arithmetically inapplicable". **The clone is not changed by
this document.**

**Change 1 — scale the OPEN TTE band by the actual window duration.**
Not a threshold change: `OPEN_TTE_HI = 840` on a 300s window is
**unreachable**, so the band is undefined there rather than loose. Justified
by the verified TTE convention (`TTE = open + duration − t`, 20,000/20,000)
and by the 2,861 pre-incentive 5m events. Unblocks **1.2% of OPENs**
(50.99% → 49.78% suppression). Small, but it is a **correctness** fix, and
the 5m slate is 45.8% of pre-incentive events by count.

**Change 2 — drop `EXTEND_MIN_AVG_IMPROVEMENT` from a hard gate to a
*price-quality ranking* input, keeping the risk caps as the binding limit.**
Justified by: the gate blocks **56.12% of all EXTENDs** across **90.85% of
events** carrying **+$5,448** of positive cash. A rule that rejects the
majority of L5's most frequent action, on activity that is net profitable,
is not reproducing L5. Unblocks **28.73% of all pre-incentive activity**
(96,637 / 336,340 fills). This is the single highest-value behavioural
change and is exactly the CLAUDE.md position that "same-side EXTEND is a
first-class action". Note the 5c number is also restated in four live
authorization bounds (`arming.py:112,143,173,198`), so changing it requires
a **new owner grant**, not an edit.

**Change 3 — raise `MAX_EXTENDS_BEFORE_COMPLEMENT` from 2 toward L5's
observed distribution, and reconcile `L5_EXTEND_BUDGET = 1` with it.**
Justified by: cap-2 blocks **49.41% of EXTENDs** (+$6,243) and the replay
harness's budget of 1 blocks **69.82%** (+$10,349) — the two copies disagree
with each other *and* both disagree with L5. Reconciling the duplicate alone
(harness 1 → policy 2) unblocks **7.1% of all activity**; lifting the policy
cap unblocks up to **25.30%**. Per CLAUDE.md, reconcile the duplicate rather
than add a third number.

**Change 4 — separate the bounded-probe ENVELOPE from the POLICY so the
policy can be replayed at L5's observed scale while the live envelope stays
exactly as frozen.** Justified by: `$12/market`, `q=1`, `8 actions`,
`6 residual`, `$4 residual principal` each suppress **87.56–99.10% of
applicable fills**, against a measured median fill of **19.22 shares** and
median event outlay of **$316.05**. This is **not** a request to raise any
live limit — "favor frequency before size", and the probe caps are correct
for the learning stage. It is the observation that with the envelope and the
policy fused, **≥87% of L5's activity is unreproducible by construction**,
so action-by-action comparison cannot run. The validation standard in
CLAUDE.md requires a replay path at observed scale; the live path keeps
every cap.

**Explicitly NOT proposed:**
- `MAX_PAIR_COST = 0.96` — **keep frozen**. The cash it blocks is
  **−$2,238**; it is suppressing the loss-making completions.
- `HARD_MAX_PRICE = 0.90` — keep. 7.70% of acquisitions, +$2,546.
- `ACQUIRE_FLOOR_S`, `L5_BAND` — keep. Both block net-negative or
  immaterial cash (−$344 and +$122).
- Any **rebate or reward** assumption. All REWARD income is
  post-2026-08-01; incentive-era economics stay **locked**.
- Any change on **depth, queue position, maker/taker flag or cancels** —
  **UNAVAILABLE**, so no rule touching them can be justified from this
  corpus.
