## Why

    "book_feed": {"connected": false, "frames": 0, "book_states": 0,
                  "last_book_age_s": null, "fresh": false,
                  "errors": ["NameError: name 'asyncio' is not defined"],
                  "source": "AUTHENTICATED_WS"}

`AuthenticatedBookFeed._run` imported `asyncio` inside its own body;
`_session` used `asyncio.wait_for` and `asyncio.TimeoutError`, which that
import never reached. The name failed to resolve on the first receive, so
no book ever arrived.

Both methods carried `pragma: no cover`, and all 20 feed tests used a
double that replaced them. The tests could not have caught this: every one
of them substituted the code that was broken.

## What this establishes

The fail-closed chain held end to end, on the first real-money attempt, and
each link is evidenced above:

  no WS -> no first book -> `wait_ready` False -> `AUTH_BOOK_NEVER_STARTED`
  -> `arm()` never called -> nothing submitted -> close-out and venue
  reconciliation still ran -> authorization consumed -> clean exit.

A reliability defect in the newest, least-proven component cost $0.00 and
one session id. That was the accepted trade when the owner chose to let the
real probe be the first production execution of this WS path, rather than
building a DISARMED feed-verification mode first.

`l5probe-20260924-btc15m-01` is spent permanently. No further authorization
was created.

verbatim.
